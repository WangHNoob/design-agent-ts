# 竞技狂欢（公会赛季）新期设计方案

## 一、活动定位

在现有竞技狂欢（个人PvP连胜 + 任务）的基础上，新增「公会战」页签，以公会为战斗单位参与赛季竞技，通过公会积分排名争夺赛季奖励。目标：提升公会凝聚力、拉动公会玩家同步活跃。

---

## 二、活动结构

活动保留原有页签，新增第三页签「公会战」：

| 页签 | 功能 | 沿用/新增 |
|------|------|----------|
| 竞技任务 | 每日/每周/挑战任务 | **沿用** |
| 竞技大赛 | 个人PvP连胜积分 | **沿用** |
| 公会战 | 以公会为单位的积分竞争 | **新增** |

时间配置与原活动保持一致，使用 `ActivityData` 统一控制开放/关闭时间；公会战子模块单独设置赛季结束与发奖时间。

---

## 三、核心玩法——公会战

### 3.1 准入规则

- 玩家**加入公会后**方可参与公会战，贡献积分记录在加入时间之后。
- 赛季中途加入公会：仅累计加入后的贡献，不继承加入前记录（对齐绝境优化中「加入公会后开始累计」的逻辑）。
- 赛季中途退出/转会：退出公会后停止为原公会累计积分；退会限制时间与发奖时间同步（参考绝境优化逻辑）。

### 3.2 积分来源

公会积分由会员个人行为汇总而来，支持以下两类途径：

| 积分来源 | 说明 | 单次积分 |
|---------|------|---------|
| **PvP胜场** | 成员在活动期间参与PvP并胜利 | 待配置 |
| **连胜加成** | 成员触发竞技大赛连胜奖励时，同步为公会加成积分 | 待配置（乘数） |
| **公会任务** | 公会战界面独立任务，条件为「公会成员累计完成X场PvP」等 | 待配置 |

> 设计意图：复用个人PvP行为数据，不引入额外战斗场景，降低研发成本。

### 3.3 公会战界面（主界面）

```
┌─────────────────────────────────────┐
│  【公会战】         本赛季剩余：X天  │
├──────────────┬──────────────────────┤
│ 我的公会信息  │   公会排行榜         │
│ 公会名：xxx  │  # 1  [公会A]  9999  │
│ 当前积分：XX │  # 2  [公会B]  8888  │
│ 我的贡献：XX │  # 3  [公会C]  7777  │
│              │  ……                  │
│ [查看任务]   │  我的公会：#X  XXXX  │
└──────────────┴──────────────────────┘
│           赛季奖励预览               │
│  前1名  ████  前3名  ███  前10名 ██  │
└─────────────────────────────────────┘
```

### 3.4 公会任务（独立任务组）

公会战页签内设专属任务，与「竞技任务」页签任务**分开管理**：

| 任务类型 | 重置周期 | 示例条件 |
|---------|---------|---------|
| 公会日常任务 | 每日重置 | 今日公会成员累计胜利X场PvP |
| 公会周任务 | 每周固定时间重置 | 本周公会成员触发连胜奖励X次 |
| 公会赛季任务 | 整个赛季不重置（挑战型） | 公会总积分达到X分 |

- 任务奖励分两部分：**个人领取奖励**（完成后由玩家自行领取）+ **公会加成积分**（自动结算入公会总分）。
- 已领取任务置底，可领取任务置顶（对齐绝境优化 UI 规范）。

### 3.5 排行榜规则

- 排行榜维度：全服公会按总积分排名。
- 榜单刷新：实时更新（或每X分钟刷新一次，待定）。
- 展示信息：名次 / 公会名 / 会长名 / 总积分 / 上赛季名次（可选）。
- 未加入公会的玩家：公会战页签显示引导提示「加入公会后参与公会战」，不显示排行榜。

### 3.6 赛季结算

| 名次档位 | 奖励发放方式 | 接收人 |
|---------|------------|-------|
| 第1名 | 邮件发放 | 会长 + 全体成员 |
| 前3名 | 邮件发放 | 会长 + 全体成员 |
| 前10名 | 邮件发放 | 会长 + 全体成员 |
| 参与奖（>0积分） | 邮件发放 | 有贡献的成员 |

> 发奖以**赛季结束时的公会归属**为准；赛季结束后X小时发奖（具体时间待配置）。

## 四、边界条件与异常处理

| 场景 | 处理逻辑 |
|------|---------|
| 赛季中途公会解散 | 已累计积分清零，成员无法获得赛季奖励；有贡献的成员保留个人参与记录（不影响个人PvP奖励） |
| 赛季中途踢出成员 | 被踢出后停止累计，发奖时以最终公会归属判断 |
| 多个公会积分相同 | 相同积分并列同名次，后达到该积分的公会排后（按达到时间戳排序） |
| 玩家未加入公会 | 公会战页签降级展示，不影响个人「竞技任务」「竞技大赛」正常使用 |
| 服务器版本限制 | 通过 `SwitchCondition` 控制公会战子模块开关，支持按服务器类型（经典服/怀旧服）差异化开放 |

## 五、关键流程

```
玩家进入竞技狂欢
    │
    ├─ [竞技任务] 完成每日/周/挑战任务 → 个人奖励
    ├─ [竞技大赛] PvP连胜 → 连胜奖励 ──→ 同步触发公会积分加成
    │
    └─ [公会战]
           │
           ├─ 查看公会排行榜 & 赛季奖励预览
           ├─ 领取公会任务 → 完成 → 领取个人奖励 + 公会积分+X
           │
           └─ 赛季结束
                  └─ 按名次邮件发放奖励给对应成员
```

## 六、配置表方案

| 配置表 | 用途 | 备注 |
|-------|------|------|
| `ActivityData` | 活动总开放时间 / 公会战子模块开放时间 | 沿用现有表，新增公会战 typeId |
| `task/_TaskBase` | 公会日常/周/赛季任务定义 | 新增公会任务类型的 taskType |
| `task/_TaskTarget` | 任务目标（如「公会成员累计胜利X场」） | 新增公会聚合目标类型 |
| `task/_TaskReward` | 公会任务个人奖励 | 沿用 |
| `SwitchCondition` | 公会战开关（按服务器类型控制） | 沿用，新增 switchName |
| `MailConfig` | 赛季结算邮件（按名次配置） | 沿用，新增赛季奖励邮件 |
| `_RankInfo` | 公会战排行榜定义 | 沿用，新增 rankType |

> **新增表（建议）**：`GuildBattleSeasonData` — 赛季积分快照、结算记录、各公会贡献成员列表，用于防止发奖时成员归属争议。

## 七、设计注意事项

1. **与现有绝境优化区分**：绝境系统已有「公会累计击败boss」的公会任务机制，公会战的任务应明确为「PvP场景专属」，避免概念混淆。
2. **未满员公会的公平性**：可考虑按「人均积分」设置次级排名维度，优先按总积分排行，总积分相同时按人均积分决定名次。
3. **反作弊**：公会战积分来源于PvP胜利，需沿用竞技大赛现有的匹配与防刷机制，避免内部刷分。
4. **UI入口**：公会战页签作为第三页签，保持整体 UI 风格与现有竞技狂欢页签一致。
