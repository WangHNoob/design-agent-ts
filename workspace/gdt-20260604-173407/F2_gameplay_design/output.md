## 一、设计目标与定位

### 1.1 设计目标

| 目标维度 | 具体描述 |
|---|---|
| **核心驱动** | 以连胜机制为个人荣誉引擎，以公会积分赛道为团队协作纽带，双轨并行激活 PvP 热度 |
| **参与覆盖** | 个人赛道保障轻度玩家有稳定产出路径，公会赛道吸引重度玩家投入团队竞争 |
| **赛程张力** | 分阶段推进 + 周节奏重置，制造持续的"截止日期压力感"与"赶超窗口期" |
| **设计边界** | 免费参与，无入场消耗，遵照知识库规定的 `entry_cost: 免费` |

### 1.2 活动定位（承接知识库）

> 竞技狂欢是一款新型限时 PvP 活动模板，旨在鼓励玩家参与 PvP 玩法，通过**连胜与任务系统**增加 PvP 热度。  
> ——来源：`activities/pvp活动模板.md`

## 二、整体赛制结构

### 2.1 赛制总体框架：「阶段积分赛 + 连胜冲榜」复合制

竞技狂欢采用**阶段推进 × 积分赛**的主体赛制，在连胜机制之上叠加阶段里程碑，形成短期目标（连胜奖励）与中期目标（阶段榜单）并存的驱动结构。

```
活动总时长（由 ActivityData 配置开放/关闭时间）
│
├── 第一阶段（热身期）  Week 1
│   ├── 个人赛道：连胜积累 + 每日/每周任务开放
│   └── 公会赛道：公会报名期 → 成员锁定 → 公会积分开始累计
│
├── 第二阶段（冲刺期）  Week 2
│   ├── 个人赛道：挑战任务解锁 + 连胜保护期（参见荣耀连战锁定规则）
│   └── 公会赛道：公会积分排名实时可见 + 团队冲刺
│
├── 第三阶段（决赛期）  Week 3
│   ├── 个人赛道：个人排行榜锁榜结算
│   └── 公会赛道：公会总积分最终排名 → 邮件发奖
│
└── 发奖期（结算后 24h 内）
    ├── 个人奖励：界面直接领取（连胜/任务奖励）
    └── 公会奖励：邮件发放（参照庆典服公会榜发奖逻辑）
```

### 2.2 积分赛制规则

**个人积分来源**

| 行为 | 积分规则 | 上限 |
|---|---|---|
| PvP 胜场 | +1 基础分/场 | 无上限 |
| 连胜触发奖励档位（3/5/7 场）| 额外加分（倍率待配置）| 按档位配置 |
| 完成每日任务 | +固定分（待配置）| 每日1次 |
| 完成每周任务 | +固定分（待配置）| 每周1次 |
| 完成挑战任务 | +固定分（待配置）| 一次性 |

**连胜重置规则（承接知识库）**

> 失败数次（可配置）后连胜重置；段位 800–1000 取消连胜状态（触发 1 次）；段位 1000–1200 扣除积分（每次扣 10 分，触发 2 次）。  
> ——来源：`systems/荣耀连战.md`

**公会积分来源**

| 行为 | 积分规则 |
|---|---|
| 成员 PvP 胜场贡献 | 成员个人积分按比例折算入公会积分（折算系数待配置）|
| 公会团队任务完成 | 公会专属任务完成后加固定分 |
| 阶段冲刺 BUFF | 第三阶段积分权重翻倍（赛制张力设计）|

## 三、双轨并行玩法逻辑

### 3.1 双轨结构总览

```
玩家进入竞技狂欢
│
├──────────────────────────────────────────────┐
│         个人赛道（Personal Track）            │
│  ┌────────────────────────────────────────┐  │
│  │  竞技任务（每日 / 每周 / 挑战任务）      │  │
│  │  竞技大赛（连胜积分冲榜）               │  │
│  └────────────────────────────────────────┘  │
│  产出：个人积分 → 个人排行榜 → 个人奖励       │
└──────────────────────────────────────────────┘
│
├──────────────────────────────────────────────┐
│         公会赛道（Guild Track）               │
│  ┌────────────────────────────────────────┐  │
│  │  公会报名 → 成员锁定 → 公会积分累计      │  │
│  │  公会团队任务 → 公会排行榜               │  │
│  └────────────────────────────────────────┘  │
│  产出：公会积分 → 公会排行榜 → 公会集体奖励   │
└──────────────────────────────────────────────┘
```

### 3.2 个人赛道详细玩法逻辑

**子系统 A：竞技任务**（承接知识库 `竞技任务` 子界面）

```
任务类型体系
│
├── 每日任务（Daily）
│   ├── 来源表：task/_DailyTask（任务类型 = 单人 2001）
│   ├── 刷新规则：每日 X 点重置（时间可配置）
│   ├── 示例任务：今日参与 PvP X 场、今日获得 X 次胜利
│   └── 状态机：未完成 → 已完成未领取 → 已领取
│
├── 每周任务（Weekly）
│   ├── 来源表：ActivityWeekPVPTask（id/type/task/param/rewards/text/jump/target）
│   ├── 刷新规则：每周固定时间重置（与荣耀连战同步逻辑）
│   ├── 示例任务：本周累计连胜 X 场、本周完成 X 次竞技大赛
│   └── 状态机：未完成 → 已完成未领取 → 已领取
│
└── 挑战任务（Challenge）
    ├── 来源表：task/_TaskBase（一次性，resetRate = 0）
    ├── 刷新规则：活动期间仅能完成一次，不重置
    ├── 示例任务：单日内完成 X 连胜、累计胜场达到 X 场
    └── 状态机：未完成 → 已完成未领取 → 已领取（永久已领取）
```

**子系统 B：竞技大赛**（承接知识库 `竞技大赛` 子界面）

```
进入特定 PvP 玩法
│
├── 开始连胜累计
│   ├── 每胜 1 场 → 连胜计数 +1
│   ├── 达到档位（3场/5场/7场）→ 触发奖励领取（界面提示）
│   └── 连胜奖励状态：可领取（高亮） / 已领取 / 未达到（灰色）
│
├── 荣耀连战锁定状态（引用 systems/荣耀连战.md 规则）
│   ├── 完成第一战 → 进入锁定状态
│   ├── 锁定期内修改装备/宝石 → 弹出操作确认弹窗
│   ├── 惩罚规则：段位 800-1000 取消连胜；段位 1000-1200 扣积分（×2次，每次-10）
│   └── 锁定解除：第二战完成 OR 当天活动时间结束
│
└── 连胜重置条件
    ├── 主动重置：玩家确认装备变更并触发惩罚
    └── 失败重置：失败达到配置次数后自动重置
```

### 3.3 公会赛道详细玩法逻辑

**整体流程**

```
公会赛道生命周期
│
Step 1. 公会报名期（活动第 1 阶段前 N 天）
│   └── 会长/副会长操作报名 → 系统校验资格 → 报名成功/失败反馈
│
Step 2. 成员锁定期（报名截止至活动结束）
│   └── 参赛名单固定 → 成员贡献积分归入本公会
│
Step 3. 积分累计期（全活动周期）
│   ├── 成员 PvP 胜场 → 自动贡献公会积分
│   ├── 公会专属任务完成 → 额外公会积分
│   └── 公会积分实时排行（活动第 2 阶段起可见）
│
Step 4. 结算与发奖（活动结束后）
│   ├── 公会榜最终排名确认
│   └── 奖励邮件发放：会长专属奖励 + 全员奖励（参照庆典服公会榜奖励逻辑）
```

**公会积分贡献规则**

- 成员个人积分（胜场积分 + 任务积分）按折算系数贡献至公会
- 退会后，已贡献积分**保留在公会**，不随成员带走（参考绝境优化退会处理逻辑）
- 活动结束前加入公会的成员，**仅累计加入后的贡献**（来源：`新绝境优化.md`："该任务需玩家加入公会后开始累计"）

## 四、公会组队规则

### 4.1 公会报名条件

| 验证项 | 规则 | 说明 |
|---|---|---|
| 公会级别 | ≥ X 级（待配置）| 防止小号公会参赛，具体数值「无参考来源，待人工补充」 |
| 公会活跃人数 | 报名时在线/活跃成员 ≥ N 人（待配置）| 保证参赛质量 |
| 会长操作权限 | 仅会长/副会长可发起报名 | 与绝境优化公会操作权限对齐 |
| 时间窗口 | 活动开始后第 1 阶段内完成报名 | 超时不可报名 |
| 重复报名 | 同一公会不可重复报名 | 幂等保护 |

### 4.2 参赛人数规则

| 规则项 | 配置说明 |
|---|---|
| **公会参赛人数上限** | 每公会最多 N 名成员贡献积分（N 待配置，建议 20–30 人）|
| **最低参赛人数** | 达到 M 人才能计入公会榜（防僵尸公会，M 待配置）|
| **积分贡献人数上限** | 每日最多取公会积分前 K 名成员的积分汇总（防止核心玩家无限刷），K 待配置 |

> ⚠️ 具体数值（N/M/K）知识库无明确记载，标注「无参考来源，待人工补充」

### 4.3 替补机制

```
替补触发场景
│
├── 场景 A：原成员报名后退会
│   ├── 已贡献积分：保留在公会
│   ├── 替补窗口：活动第 1 阶段内可补充报名空缺席位
│   └── 替补成员：加入后从加入时刻起开始贡献积分（不补算历史积分）
│
├── 场景 B：报名人数未满额
│   └── 活动第 1 阶段内，会长可追加成员至上限人数
│
└── 场景 C：活动第 2 阶段起（冲刺期）
    └── 替补窗口关闭，名单锁定，不再接受新成员贡献公会积分
```

**替补规则设计依据**

> 退会限制相关与发奖时间同步，而非战斗时间。  
> ——来源：`systems/新绝境优化.md`

参照此逻辑，竞技狂欢公会赛道的**退会积分保留**与**替补锁定时间节点**均与发奖时间对齐，而非以战斗/活动结束时间为准。

### 5.2 每日节奏规划

```
每日节奏（Day D）
│
├── 00:00  每日任务刷新（task/_DailyTask 重置）
├── 活动开放时段  玩家参与 PvP → 连胜累计 → 荣耀连战锁定状态生效
├── 任意时段  完成每日/每周任务 → 领取奖励（界面直接领取）
```

### 5.3 每周节奏规划

```
每周节奏
│
├── 周一（或配置重置时间点）
│   ├── 每周任务进度重置
│   ├── ActivityWeekPVPTask 下发新一周任务池
│   └── 公会阶段任务进度重置（参照绝境优化每周固定时间重置逻辑）
│
├── 周一~周六  正常积分累计期
│
└── 周日（或配置发奖时间点）
    ├── 本周排行榜快照
    └── 本周段位奖励结算
```

### 5.4 阶段里程碑事件

| 时间节点 | 事件描述 | 触发条件 |
|---|---|---|
| 第一阶段结束 | 公会报名窗口关闭；替补窗口同步关闭 | `T+7` |
| 第二阶段开始 | 公会排行榜对所有参赛玩家可见 | `T+7` |
| 第三阶段开始 | 公会积分权重进入翻倍期；挑战任务最后冲刺 | `T+14` |
| 活动结束 | 个人榜单锁榜；公会积分最终快照 | 配置时间 |
| 发奖时间 | 公会奖励邮件发送；个人奖励界面可领取 | 结束后 ~24h |

## 八、边界条件与异常处理

### 8.1 个人赛道边界

| 场景 | 处理规则 |
|---|---|
| 活动时间外参与 PvP | 不计入竞技狂欢积分，不触发连胜奖励 |
| 任务到期未领取 | 每日任务随每日重置一并清除；每周任务随每周重置清除 |
| 挑战任务重复触发 | `canGetAnotherOrNot = 否`，界面显示"已领取"灰态 |
| 段位变更影响惩罚规则 | 以触发惩罚时的段位为准，实时判定 |

### 8.2 公会赛道边界

| 场景 | 处理规则 |
|---|---|
| 会长在活动期间转让/退出 | 新会长继承报名资格，参赛名单不变 |
| 公会解散 | 解散时的积分作废，成员个人积分保留 |
| 成员未满最低参赛人数 | 不计入公会榜单，但成员个人积分正常计算 |
| 替补成员晚于锁定时间加入 | 加入后个人积分正常计算，但**不贡献**公会积分 |
| 跨周退会再加入 | 再加入后重新从加入时刻起累计（不补算）|

## 十、设计总结

竞技狂欢核心玩法框架以**知识库既有的连胜机制与任务体系**为基础支柱，向上扩展出**个人赛道（任务驱动 + 连胜冲榜）** 与 **公会赛道（团队报名 + 积分贡献 + 集体荣誉）** 的双轨并行结构。三阶段赛程（热身期 → 冲刺期 → 决赛期）在 21 天周期内制造连续的目标感与紧迫感，公会替补机制与退会积分保留规则均严格参照知识库现有逻辑扩展，确保实现成本可控、系统一致性强。
