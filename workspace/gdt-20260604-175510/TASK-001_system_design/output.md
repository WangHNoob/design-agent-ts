## 一、活动定位与设计目标

### 1.1 活动定位

「竞技狂欢」是以 PvP 竞技为核心的限时活动，在原有「竞技狂欢」PvP 活动模板基础上，扩展双模式玩法框架——引入 **个人竞技模式**（个人独立积分竞争）与 **公会团战模式**（公会成员贡献汇总，进行公会排名）。

### 1.2 设计目标

| 目标维度 | 说明 |
|---------|------|
| 玩家活跃 | 通过双模式驱动 PvP 热度，增加每日在线时长 |
| 社交粘性 | 公会团战模式强化公会凝聚力，促进成员间协作 |
| 竞争张力 | 个人榜与公会榜双排行榜提供多层次竞争目标 |
| 留存驱动 | 任务体系（每日/每周/挑战）形成稳定回访动力 |

### 1.3 知识库依据

- 活动框架继承自 Wiki：`activities/pvp活动模板.md`（竞技狂欢 PvP 活动模板）

- 任务体系：`tables/task.md`（`task/_TaskBase`、`task/_TaskTarget` 等）

## 三、核心玩法框架与核心循环

### 3.1 整体玩法框架

```
活动开放期间
    │
    ├─────────────────────────────────────────────────┐
    │  【个人竞技模式】                                │  【公会团战模式】
    │  玩家在 PvP 玩法中独立参赛                      │  公会报名 → 成员参赛
    │  ↓ 获得个人积分                                 │  ↓ 成员获得贡献值
    │  连胜触发额外积分加成                           │  成员贡献汇总 → 公会总分
    │  ↓                                              │  ↓
    │  个人榜排名更新                                 │  公会榜排名更新
    │                                                 │
    └─────────────────┬───────────────────────────────┘
                      │
              ↓ 每日/每周/挑战任务并行驱动
              ↓ 连胜奖励可即时领取
              ↓ 活动结算 → 排行榜快照
              ↓ 邮件/界面发放排名奖励
```

### 3.2 核心循环（每日）

```
玩家登录
  → 查看竞技狂欢活动入口（红点提示）
  → 进入活动主界面
      ├─ 查看今日任务进度 → 参与 PvP 玩法
      │       ↓ 完成任务 → 领取任务奖励
      ├─ 参与个人竞技
      │       ↓ 积累连胜 → 达到门槛 → 领取连胜奖励
      │       ↓ 个人积分增加 → 个人榜排名上升
      ├─ 参与公会团战（需公会已报名）
      │       ↓ 战斗结果产生个人贡献值
      │       ↓ 贡献值累加至公会总分 → 公会榜排名变化
      └─ 查看排行榜 → 了解当前竞争态势
```

## 四、公会报名与参赛机制设计

### 4.1 报名条件

| 条件项 | 规则说明 | 配置来源 |
|--------|---------|---------|
| 公会等级门槛 | 公会等级 ≥ 配置值（默认建议 3 级）| `CarnivalGuildEnroll.minUnionLev` |
| 最低参赛人数 | 已确认参赛成员数 ≥ 配置值（建议 ≥ 5 人） | `CarnivalGuildEnroll.minJoinNum` |
| 报名时间窗口 | 活动开始前 N 小时（可配置）内可报名 | `CarnivalGuildEnroll.enrollDeadlineHour` |
| 操作权限 | 仅会长/副会长可发起报名 | 读取 `union/UnionLev`（`maxMemberNum` 相关权限） |

### 4.2 报名流程

```
会长/副会长打开公会团战界面
  → 系统校验：公会等级 ≥ 门槛 & 在报名时间窗口内
    ├─ 不满足 → 提示不可报名原因
    └─ 满足 → 显示「报名」按钮
          ↓
  会长点击报名 → 弹出确认弹窗（展示当前可参赛成员列表）
          ↓
  确认报名 → 服务端写入报名记录（状态：已报名/待开赛）
          ↓
  成员收到公会频道通知「本公会已报名竞技狂欢，快来参加！」
          ↓
  活动开赛 → 已报名公会自动进入公会榜竞争
```

### 4.3 参赛成员确认

- 报名后，成员可在公会团战页面「参赛确认」（可选设计，增强仪式感）
- 成员参与任意 PvP 对战（且产生贡献积分）即视为实际参赛
- 若实际参赛人数低于最低参赛人数（整个活动周期结束时判断），公会不参与公会榜结算

## 五、公会内成员贡献度记录机制

### 5.1 贡献值定义

> 贡献值（Contribution Score）= 玩家在公会团战模式下参与 PvP 战斗所产生的积分，与个人模式积分分开计算。

| 触发场景 | 贡献值规则 |
|---------|-----------|
| PvP 胜利 | 基础贡献值 × 胜利系数（可配置） |
| PvP 失败 | 基础贡献值 × 失败系数（> 0，鼓励参与） |
| 连胜加成 | 达到连胜门槛时，额外贡献值奖励（与个人连胜奖励共享触发） |
| 每日上限 | 单玩家单日贡献值上限（防刷控制，可配置） |

### 5.2 贡献值汇总

```
成员 A 产生贡献值 Va
成员 B 产生贡献值 Vb
成员 C 产生贡献值 Vc
       ↓
公会总分 = ΣVi （所有成员当日贡献值之和）
       ↓
公会总分累积 → 公会榜实时更新
```

### 5.3 贡献度记录数据结构

**服务端数据（玩家级，运行时数据）**：

```
PlayerGuildContrib {
    playerId       // 玩家ID
    guildId        // 所属公会ID（活动期间）
    seasonId       // 活动赛季ID
    totalContrib   // 累计贡献值（全活动周期）
    todayContrib   // 今日贡献值（每日0点重置）
    contribRank    // 公会内贡献排名（实时计算）
    joinDate       // 首次参赛日期
}
```

**服务端数据（公会级，运行时数据）**：

```
GuildSeasonData {
    guildId          // 公会ID
    seasonId         // 活动赛季ID
    totalScore       // 公会总分（累计）
    enrollStatus     // 报名状态（0未报名/1已报名/2参赛中/3已结算）
    actualJoinNum    // 实际参赛人数
    rankSnapshot     // 最终排名快照（结算时写入）
}
```

## 六、双排行榜系统设计

### 6.1 个人榜

| 属性 | 说明 |
|------|------|
| 榜单名称 | 个人竞技榜 |
| 排名依据 | 玩家个人活动积分（个人竞技模式下累计） |
| 显示内容 | 名次、头像、昵称、服务器、个人积分、奖励预览 |
| 更新频率 | 实时更新（写入后即刻排序） |
| 展示上限 | 显示前 100 名；本人排名不在前 100 时单独显示本人排名 |
| 结算时机 | 活动 `playerEndTime` 截止，榜单快照锁定 |
| 奖励发放 | 活动 `rewardTime` 时邮件发放（参考 `MailConfig` 体系） |

### 6.2 公会榜

| 属性 | 说明 |
|------|------|
| 榜单名称 | 公会团战榜 |
| 排名依据 | 公会总分（所有成员贡献值之和） |
| 显示内容 | 名次、公会旗帜、公会名、公会等级、成员数、公会总分、奖励预览 |
| 更新频率 | 实时更新 |
| 展示上限 | 显示前 50 名；本公会未在前 50 时单独显示本公会排名 |
| 点击交互 | 点击公会条目可展开成员贡献详情（Top10贡献者） |
| 结算时机 | 活动 `playerEndTime` 截止，榜单快照锁定 |
| 奖励发放 | `rewardTime` 时：会长+全员邮件（参考庆典服专属活动公会榜奖励模式） |

### 6.3 榜单联动说明

- 个人竞技积分与公会贡献值**分开计算**，互不影响
- 同一场 PvP 战斗对战结果：
  - 若玩家所在公会已报名 → 战绩同时计入个人积分 & 公会贡献值
  - 若公会未报名 → 战绩仅计入个人积分

## 八、与现有公会系统的交互逻辑

### 8.1 数据读取接口（活动 → 公会系统）

| 读取数据 | 来源表 | 用途 |
|---------|--------|------|
| 公会当前等级 | `union/UnionLev.level` | 校验公会报名门槛 |
| 公会当前成员数 | `union/UnionLev.maxMemberNum`（上限字段，实际人数由服务端接口提供） | 校验最低参赛人数 |
| 成员角色权限 | 公会服务端接口（会长/副会长标识） | 控制报名操作权限 |
| 公会名称/旗帜 | 公会基础数据接口 | 公会榜展示 |

### 8.2 数据写回接口（活动 → 公会系统）

| 写入数据 | 写入位置 | 时机 |
|---------|---------|------|
| 活动贡献值（公会维度） | 活动专属贡献字段（**不影响常规公会贡献字段**） | 每次 PvP 战斗结算后异步写入 |
| 公会报名状态 | 活动侧数据库（`GuildSeasonData`） | 会长确认报名时 |

> **隔离原则**：活动公会总分与常规公会贡献值（`union/UnionStoreroomDonate.getContribution`）严格隔离，活动结束后活动数据归档，**不回写**公会常规积分，避免污染长期公会数据。

### 8.3 公会系统交互流程图

```
┌─────────────────┐     读公会等级/成员数      ┌──────────────────┐
│  竞技狂欢        │ ──────────────────────── → │  公会系统         │
│  公会团战模块    │                            │  (union 表族)     │
│                 │ ← ─────────────────────── │                  │
│                 │     返回公会数据            │                  │
│                 │                            │                  │
│ 报名校验通过     │ ──（写入报名状态）────────→ │  活动数据存储     │
│ 战斗结算        │ ──（写入贡献值）──────────→ │  (活动侧，隔离)   │
│ 结算发奖        │ ──（触发邮件发放）─────────→ │  MailConfig 体系 │
└─────────────────┘                            └──────────────────┘
```

### 8.4 公会解散/退出处理

| 场景 | 处理规则 |
|------|---------|
| 活动期间公会解散 | 已有贡献值保留，公会从排行榜移除，不参与结算 |
| 成员退出公会 | 已产生的贡献值保留计入公会（快照时记录），退出后新增贡献不再计入原公会 |
| 成员转移公会 | 转移后新增贡献计入新公会；已贡献值归属原公会 |

## 十、配表结构设计（Markdown 方案）

### 10.1 活动基础配置表 `CarnivalActivityConfig`

| 字段名 | 类型 | 约束 | 说明 |

## 十一、关键边界条件与异常处理

| 场景 | 处理方案 |
|------|---------|
| 活动时间外访问 | 入口隐藏（`SwitchCondition.open=0`）；若已有数据则展示历史结果 |
| 公会报名后人数降至门槛以下 | 已报名状态保持，但结算时判断实际参赛人数，不足则不参与公会榜奖励 |
| PvP 对战掉线/异常结束 | 按失败处理，不计入积分/贡献，由战斗系统统一处理 |
| 排行榜积分相同 | 先达到该积分者排名靠前（时间戳 tiebreak） |
| 活动期间公会合并/改名 | 以 `guildId` 为唯一标识，名称变更实时同步，合并时取合并后公会ID |
| 连胜数越界 | 连胜达最高档后不再累积，下次失败重置至0 |
| 重复领取奖励 | 服务端幂等校验，奖励发放标记位防止重复发放 |
