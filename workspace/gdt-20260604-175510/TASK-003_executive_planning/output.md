## 四、公会团战赛程编排

### 4.1 赛制选型分析

| 赛制方案 | 优点 | 缺点 | 适用场景 |
|---------|------|------|---------|
| **纯积分赛（推荐）** | 实现简单，无需分组逻辑；全程参与感强 | 顶部差异易拉大 | 首次上线，降低开发复杂度 |
| 分组淘汰赛 | 竞争更激烈，戏剧性强 | 实现复杂，需分组算法；小公会早出局留存差 | 成熟版本迭代 |
| 分组积分+总决赛 | 兼顾公平性与激烈度 | 开发成本最高，周期需拉长 | 长线运营版本 |

> **本次采用：纯积分赛制**（参考 `integral/IntegralHonorUnionScore` 的 `ratio` 折算积分赛范式，以及 `UnionWar/UnionWarSeason` 的赛季设计）。后续版本可升级为分组积分赛。

### 4.2 公会团战赛程编排表

```
公会团战赛程（14天，积分制）

阶段       时间段           主要内容
─────────────────────────────────────────────────────
📋 报名期  D-2 ～ D-1       公会完成报名确认
🚀 热身期  D0 ～ D+3        积分累计，公会摸底排名
⚔️  竞技期  D+4 ～ D+10     主要积分产出，榜单变动频繁
🔥 冲刺期  D+11 ～ D+14     高频争夺，公会动员全成员
🏆 结算期  D+14 00:00       榜单快照，排名锁定
🎁 发奖期  D+14 06:00       邮件奖励发放
```

### 4.3 公会赛阶段运营节拍

| 阶段 | 时段 | 公会特色运营动作 |
|-----|------|--------------|
| **热身期** | D0～D+3 | 每日公会积分榜（Top10）公示；鼓励会长动员成员参赛 |
| **竞技期** | D+4～D+10 | 公会间排名变动播报；「本周贡献 MVP」内部榜公示 |
| **冲刺期** | D+11～D+14 | 每日发送公会差距通知；公会连胜里程碑特别播报 |

### 4.4 是否分组的设计决策

| 当前决策 | 理由 |
|---------|------|
| **本赛季不分组** | 参赛公会约 30～80 个/服，规模适中，单榜竞争即可保证张力；分组会稀释榜单可见度 |
| **下赛季可选升级** | 若参赛公会超过 100 个/服，可引入 `UnionWarGrade.unionActiveMin` 类似的活跃门槛分组逻辑 |

## 七、风险预案（反作弊与异常处理）

### 7.1 已知风险清单与应对措施

#### 风险一：个人霸榜（脚本刷场次）

| 维度 | 详情 |
|-----|------|
| **风险描述** | 玩家使用脚本工具全天候刷 PvP 场次，突破正常玩家积分上限 |
| **触发信号** | 单日场次 > 30（超出正常上限 20 场 50% 以上）；连胜率 > 95% |
| **防护层 1（配置）** | 日积分上限 600 分硬封顶，超出不计分。引用 `_IntegralFightChange.sameDayMaxMatchCount` 范式 |
| **防护层 2（监控）** | 服务端实时监控单玩家日场次，超过 25 场触发风险标记 |
| **防护层 3（自动处置）** | 引用 `_IntegralRisk.autoBannedPlayer + bannedMinute` 机制：超出阈值自动临时封禁 PvP 功能（如 30 分钟冷却） |
| **防护层 4（人工）** | BI 后台每日产出「异常积分玩家名单」，运营人工复核，确认后执行积分扣除或封禁 |
| **配置参考** | `CarnivalAntiCheat.riskLevel` 表，参考 `_IntegralRisk` 和 `_IntegralContinueRisk` |

#### 风险二：公会恶意刷分（同公会互打）

| 维度 | 详情 |
|-----|------|
| **风险描述** | 同一公会成员互相对战，双方均获得胜利积分 / 贡献值，远超真实对战产出 |
| **触发信号** | 同IP双方；短时间内频繁匹配同一对手；双方均为同公会成员 |
| **防护层 1（系统）** | 服务端检测对战双方是否同属一个公会（读取 `guildId`），若是则本场**公会贡献值计为 0**（个人积分仍正常计）|
| **防护层 2（匹配）** | 匹配系统增加规则：24h 内与同一玩家对战超过 3 次，第 4 次起匹配权重下降（`repeatMatchControl` 字段参考 `_IntegralArenaArea`） |
| **防护层 3（监控）** | BI 监控：公会积分增速异常（单日公会总分 > 正常上限 150% 触发人工复核） |
| **处理规则** | 核实后：扣除异常贡献值，涉事账号当日积分清零；情节严重取消公会本活动资格 |

#### 风险三：小号注水（号群控制结算排名）

| 维度 | 详情 |
|-----|------|
| **风险描述** | 玩家控制大量小号故意输给主号，刷高主号积分；或公会向小号账号发放参赛名额稀释其他公会 |
| **防护层 1（参与资格）** | 个人榜奖励领取需满足「有效参与」条件：总场次 ≥ 10 场 且 个人积分 ≥ 200 分 |
| **防护层 2（战力验证）** | 参考 `_IntegralFightPowerMatch` 的战力区间匹配，实力悬殊对战（战力差 > 5 倍）的积分打折（×0.3）|
| **防护层 3（账号检测）** | 同 IP / 同设备多账号登录检测；新注册账号（< 7 天）不可参与排名结算（仅可参与任务） |
| **防护层 4（人工）** | 结算前 24h 人工复查前 20 名异常账号 |

#### 风险四：公会报名资格滥用

| 维度 | 详情 |
|-----|------|
| **风险描述** | 公会临时拉人达到报名门槛，活动结束后退人；或多个公会利益共享人员流动 |
| **防护层 1** | 参赛成员认定以活动截止时当前在会状态为准（不认定历史曾在会）|
| **防护层 2** | 成员参赛期间退会：退会后 24h 内新贡献不计入原公会（防止临时拉人打完立刻踢） |
| **防护层 3** | 公会结算时校验实际参赛成员数 ≥ `minJoinNum`，低于门槛不参与公会榜奖励 |

#### 风险五：奖励发放异常

| 维度 | 详情 |
|-----|------|
| **风险描述** | 结算时排名错误、邮件重复发放、玩家未收到奖励 |
| **防护层 1** | 快照写入采用事务锁，确保原子性 |
| **防护层 2** | 邮件发放复用 `_GetRewardAudit` 幂等校验机制（`limitType + limitTimes`） |
| **防护层 3** | 发放后 2h 内运营监控「已发放/未发放」比率，异常立即介入 |
| **兜底方案** | 邮件发放失败的玩家，运营后台手动补发（`_AwardSend` 手动派发工具）|

### 7.2 风险应对决策树

```
检测到异常 → 【自动分级处置】
    │
    ├─ 积分异常（超限 < 50%）
    │     → 警告日志 + BI 标记，不立即处置
    │
    ├─ 积分异常（超限 50%～200%）
    │     → 触发自动积分扣除 + 发送警告邮件给玩家
    │
    ├─ 积分异常（超限 > 200%）或同会互打检出
    │     → 自动临时封禁（30min）+ 升级人工复核队列
    │
    └─ 人工复核确认作弊
          ├─ 个人作弊 → 积分清零 + 取消排名资格 + 封禁天数
          └─ 公会作弊 → 公会贡献值回滚 + 情节严重取消公会资格 + 全服公告
```
